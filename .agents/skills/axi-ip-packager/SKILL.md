# AXI IP Packager Skill

Guides the architectural wrapping of RTL acceleration cores into AXI-compliant interfaces for integration with the Zynq Processing System (PS).

## 1. When to Use
- Wrapping RLE, LZ4, AES-CTR, or ChaCha20 RTL cores into AXI4-Lite slaves for register-based control and status.
- Designing AXI4-Stream interfaces for bulk streaming of uncompressed/ciphertext blocks.
- Verifying handshake compliance (`VALID` before `READY` rules).
- Documenting and maintaining the address map in `cora7z/app/hw/src/INTERFACES.md`.

## 2. AXI4-Lite Control Slave Standard
All accelerator cores instantiated in the PL fabric expose an AXI4-Lite slave interface with 32-bit registers:
- `REG 0 (0x00)`: Control (`bit 0`: start, `bit 1`: reset_core, `bit 2`: enable_irq)
- `REG 1 (0x04)`: Status (`bit 0`: busy, `bit 1`: done, `bit 2`: error)
- `REG 2 (0x08)`: Input Block Size (Bytes, 32-bit)
- `REG 3 (0x0C)`: Output Block Size (Bytes, 32-bit)
- `REG 4 (0x10)`: Hardware Latency Cycles (read-only counter)

## 3. Handshake Invariants
- **No Cyclic Dependency**: An AXI master or slave must never assert `VALID` conditionally dependent on `READY`. `VALID` must be asserted unconditionally when data is ready and remain held until `READY` is asserted.
- **Single Clock Domain**: AXI-Lite registers must be clocked by `s_axi_aclk` (`FCLK_CLK0` from PS7).
- **Address Decoding**: Return `BRESP = "00"` (OKAY) for valid register addresses, and `BRESP = "10"` (SLVERR) or default zero for unmapped addresses to avoid bus stall.

## 4. Synchronization with `INTERFACES.md`
Whenever a register offset or bit definition changes:
1. Update `cora7z/app/hw/src/INTERFACES.md`.
2. Confirm the base address assigned in Vivado Address Editor matches `xparameters.h` generated by Vitis.
